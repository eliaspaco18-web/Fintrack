The faint light token was darkened to `#626D7E` after an earlier canvas pairing measured only 4.35:1.

## Visual inspection and corrections

The captures were inspected as rendered browser output. Iteration corrected chart-label scaling, metadata legibility, credit-row wrapping at 320 px, repeated mobile create controls, tablet commitment spacing, dashboard budget ordering and a misleading dropdown-like month affordance. The final desktop/dashboard/table/form captures use the same synthetic fixture and local font family.

An earlier run failed on credit overflow at 320 px; that failure was corrected and the same assertion passed in subsequent runs. Earlier screenshot runs could retain a toast during hash-only navigation; each capture now begins from a blank document. Drawer/form captures use the actual viewport rather than including unrelated offscreen page content. Full-page mobile screenshots still place fixed navigation at its initial viewport location; captures 19–20 show actual scrolled viewport behavior.

One attempted browser rerun was temporarily blocked by the automatic approval review service's usage limit. After its stated reset time and the owner's continuation, the same approved execution path succeeded. No approval bypass or alternative execution mechanism was used; this is no longer an outstanding blocker.

## Remaining verification gaps

1. Full keyboard/screen-reader review, focus restoration across every secondary action, 200% zoom, real iOS/Android browser behavior and reduced-motion inspection remain implementation acceptance work. Native dialog behavior in this simulator is not a certification of the production overlay.
2. Not every module, viewport and state has a screenshot. The high-fidelity core is Dashboard, Transactions, Accounts, Budgets and Credits; other pages are representative supporting surfaces. The master plan supplies screen-by-screen operational specifications for all modules.
3. The simulator does not prove attachment safety, live financial calculations, permission boundaries, persistence, mutation reconciliation, imports or authentication. Preserve and test the real implementations independently.
4. No usability sessions or production performance benchmarks were conducted. The five-person usability criteria and timing thresholds in the master plan are targets, not measured outcomes.
5. S01 requires urgent, separately authorized verification of the summary RPC's effective ownership checks/grants in a disposable database. Static evidence does not establish what is deployed or prove exploitation.
6. Local main was previously observed behind the known remote by three commits. There was no fetch/merge; reconcile the eventual implementation SHA and any newer work before applying the design.

## Reproduce

From the repository root, with existing Node and repository Playwright dependencies available:

```sh
node --check docs/redesign-v3/preview/app.js
node --check docs/redesign-v3/preview/serve.mjs
node --check docs/redesign-v3/preview/verify.mjs
./node_modules/.bin/playwright test --config=playwright.unit.config.ts
```

In one terminal, start the static server:

```sh
node docs/redesign-v3/preview/serve.mjs
```

In another terminal, run:

```sh
node docs/redesign-v3/preview/verify.mjs
```

The browser test writes only proposal captures and `verification.json` under `docs/redesign-v3/screenshots/`. It may require explicit local browser-launch permission under the Codex sandbox. Do not weaken the sandbox or use production credentials to make it run. The server uses port 4173; the verifier intentionally targets that exact localhost origin.

## Release boundary

For actual implementation, use the master plan's financial golden fixtures, per-module state matrix, stage dependencies, safe authenticated environment, visual tolerances, protected-route checks and rollback criteria. Existing historical QA checkmarks do not replace new evidence for the changed implementation. Do not merge or release a redesigned route on the strength of these synthetic screenshots alone.
