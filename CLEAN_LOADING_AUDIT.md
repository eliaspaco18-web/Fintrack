## Portfolio Stability Fix Re-check

The prior portfolio stability fix is present on current `origin/main`.

- `app/(dashboard)/portfolio/page.tsx`
  - Uses server query timeout via `withTimeout`.
  - Loads `accounts`, `bank_entities`, and `user_currencies` with `Promise.allSettled`.
  - Computes `preloadError` for failed preload segments and passes it to the client.
- `components/management/PortfolioManager.tsx`
  - Uses client timeout with `AbortController` for portfolio fetches.
  - Shows `DataErrorBanner` with retry.
  - Avoids replacing a blocking load error with the empty portfolio state.
  - Opens create modal for `?new=portfolio`.
- `components/layout/Topbar.tsx`
  - Quick action now links to `/portfolio?new=portfolio`.

## RLS / Query Mismatch Symptoms To Watch

These require approval before any production or schema/RLS changes.

- Server preload returns empty data while API retry succeeds.
- API returns `ok: true, data: []` for a user that should have data.
- Joined selects fail while base table selects succeed, especially `accounts -> bank_entities`, `budget_periods -> budget_series`, `installments -> loans`, and asset type joins.
- Preview and production differ for the same user and commit.
- Errors mention missing relations, columns, policies, or permission denied.

## Recommended Vercel Audit Procedure

1. Use one test user with known data in every module.
2. Test preview and production on the same commit.
3. Hard refresh each route with browser cache disabled.
4. Capture Network waterfall, Vercel function duration, and console errors.
5. For each module, block one dependent API route at a time and confirm visible error/retry.
6. Compare first visit vs second visit to detect SWR/browser-cache masking.
7. Do not change Supabase RLS, schema, auth, middleware, API contracts, or Vercel environment variables without owner approval.
